1 Qué se despliega

Responsable de sistemas

Este manual explica cómo convertir el repositorio FrontTRT en instaladores y cómo dejarlos funcionando en las computadoras de cada sucursal. También cubre la publicación del backend y la preparación de una sucursal nueva (capítulos 10 y 11). Los comandos se ejecutan en una terminal abierta en la raíz del repositorio del que trata el capítulo.

1.1 Piezas del sistema

PiezaDónde correQuién la despliega
Aplicación de escritorioEn cada caja, como programa instalado (Electron).Este manual.
API RESTRender, en https://refaccionariaback.onrender.com/api.Repositorio RefaccionariaBack. GitHub Actions lo publica (capítulo 10).
Base de datosPostgreSQL en Neon.Migraciones del backend (sección 10.3).

La aplicación de escritorio no guarda datos del negocio. Todo lo que muestra lo pide a la API, así que cada caja necesita internet para trabajar.

1.2 Artefactos

electron-builder deja los instaladores en dist_electron/. El nombre lleva el número de versión de package.json.

Archivo (versión 1.0.0)SistemaTamañoNotas
FrontTRT-1.0.0.AppImageLinux x64138 MBUn solo archivo ejecutable. No se instala.
front-trt_1.0.0_amd64.debDebian, Ubuntu y derivados x64104 MBSe instala con apt y aparece en el menú de aplicaciones.
FrontTRT Setup 1.0.0.exeWindows x64110 MBInstalador NSIS. Va acompañado de un .blockmap que no hace falta copiar.

Tamaños de la compilación de abril de 2026.

macOS

package.json declara un destino dmg para macOS, pero nunca se ha compilado ni probado. Generarlo requiere una Mac.

2 Requisitos

Responsable de sistemas

2.1 Equipo de compilación

Es la computadora donde se generan los instaladores. Lo más sencillo es un Linux x64, porque desde ahí salen los tres formatos.

ProgramaVersiónPara qué
Node.js y npmNode 22 y npm 10Compilar. La última compilación se hizo con Node 22.23.4 y npm 10.9.9.
Gitcualquiera recienteObtener el código.
binutilsla del sistemaSolo en Linux, para armar el .deb.
Dockercualquiera recienteSolo para generar el instalador de Windows desde Linux.
Espacio en discounos 3 GB libresDependencias, la imagen de Docker (cerca de 1 GB) y los tres instaladores.

La primera compilación necesita internet: npm descarga las dependencias y electron-builder descarga los binarios de Electron a ~/.cache/electron.

2.2 Cajas de las sucursales

  • Computadora de 64 bits con Windows 10 u 11, o con un Linux de escritorio (Ubuntu, Debian, Linux Mint o similar).
  • Conexión a internet estable hacia refaccionariaback.onrender.com.
  • Pantalla de 1280 × 800 o mayor. La ventana abre en 1200 × 800.
  • Lector de código de barras USB que funcione como teclado y mande Enter al final. No necesita controlador.
  • La sucursal dada de alta, con usuarios, métodos de pago y existencias (capítulo 11). Sin sucursal, el usuario no puede vender.
Impresora

La versión 1.0 arma el ticket en formato ESC/POS pero todavía no lo envía a la impresora térmica. El ticket se ve en pantalla y se consulta en Historial. No es necesario conectar la impresora para esta versión.

3 Preparar el código

Responsable de sistemas

3.1 Obtener e instalar dependencias

  1. Clona el repositorio, o actualiza tu copia, y cámbiate a la rama que vas a liberar.
  2. Instala las dependencias exactas de package-lock.json:
npm ci

npm ci rearma node_modules desde el lock, así dos compilaciones del mismo commit usan las mismas versiones.

3.2 Apuntar al backend

La dirección de la API queda fija dentro del instalador en el momento de compilar. Se toma de src/env/environment.prod.ts:

apiUrl: 'https://refaccionariaback.onrender.com/api',

Si el backend cambia de dirección, edita apiUrl y vuelve a generar todos los instaladores; en una caja ya instalada no se puede cambiar. Los otros archivos de src/env/ son para desarrollo y pruebas y nunca llegan a un instalador.

3.3 Número de versión

Sube el campo "version" de package.json antes de cada liberación, por ejemplo de 1.0.0 a 1.0.1. Ese número va en el nombre de los instaladores y es el que reporta la aplicación. Si no lo cambias, el instalador nuevo se llama igual que el anterior y es fácil confundirlos.

3.4 Revisar antes de compilar

El repositorio no tiene integración continua. Corre estas revisiones a mano y no sigas si alguna falla:

npm run lint          # debe terminar sin errores
npm run test:coverage # pruebas en verde y cobertura mínima
npm run e2e           # pruebas de extremo a extremo con la API simulada

4 Compilar Angular

Responsable de sistemas

Este paso convierte el código Angular en archivos estáticos. Los comandos de empaquetado del capítulo 5 ya lo incluyen; córrelo por separado cuando quieras revisar la compilación antes de empaquetar.

npm run build:prod

El resultado queda en dist/front-trt/browser/, unos 1.7 MB. La compilación tarda menos de 10 segundos en un equipo actual y termina con Application bundle generation complete.

Hoy aparecen tres avisos de presupuesto, y no detienen la compilación:

AvisoSignificado
bundle initial exceeded maximum budgetEl paquete inicial pesa 615 kB y el aviso salta en 500 kB. El error sería en 1 MB.
inventory-product-card.component.css exceeded…Estilos de 6.67 kB contra un aviso de 4 kB.
admin-management.page.css exceeded…Estilos de 4.15 kB contra un aviso de 4 kB.

Un mensaje que diga [ERROR] sí detiene la compilación y no se genera nada.

Archivos de root

Si antes se generó el instalador de Windows con Docker (sección 5.2), parte de dist/ y dist_electron/ queda a nombre de root. La compilación falla al final con EACCES: permission denied, rmdir y deja dist/front-trt/browser/ incompleto. Devuelve los archivos a tu usuario y vuelve a compilar:

sudo chown -R "$USER":"$USER" dist dist_electron node_modules

5 Empaquetar el escritorio

Responsable de sistemas

electron-builder toma dist/front-trt/, la carpeta electron/ y package.json, y los empaqueta junto con Electron. La configuración está en la sección "build" de package.json.

5.1 Linux: AppImage y .deb

  1. Si es la primera vez, instala binutils: sudo apt install binutils.
  2. Compila y empaqueta:
npm run build:installer   # = npm run build:prod && electron-builder
  1. Al terminar, revisa que dist_electron/ tenga el .AppImage y el .deb con la versión nueva en el nombre.
Archivos viejos

dist_electron/ conserva los instaladores de compilaciones anteriores, incluido un FrontTRT-0.0.0.AppImage de antes de fijar la versión. Antes de copiar a las cajas, confirma por nombre y fecha que tomas el archivo correcto.

5.2 Windows desde Linux con Docker

build-win.sh corre la compilación dentro de la imagen electronuserland/builder:wine, que trae Wine para generar el instalador de Windows sin salir de Linux.

  1. Confirma que Docker está corriendo: docker info no debe dar error.
  2. Ejecuta:
npm run build:installer:win
  1. La primera vez se descarga la imagen, cerca de 1 GB. Las siguientes reutilizan la imagen y las cachés de ~/.cache/electron y ~/.cache/electron-builder.
  2. Dentro del contenedor se ejecutan npm install, npm run build:prod y npm run build:win. Al terminar, el script imprime si la construcción salió bien.
  3. Busca FrontTRT Setup X.Y.Z.exe en dist_electron/.
  4. Devuelve los archivos a tu usuario con el chown del capítulo 4. Si no lo haces, la siguiente compilación en Linux falla.

5.3 Windows desde Windows

En una PC con Windows, Node 22 y Git, sin Docker:

npm ci
npm run build:installer

En Windows, build:installer genera el instalador NSIS en lugar del AppImage y el .deb.

6 Instalar en las cajas

Responsable de sistemas

Copia el instalador a la caja con una memoria USB o una carpeta compartida. Usa siempre el archivo de dist_electron/ de la compilación que revisaste.

6.1 Linux con AppImage

  1. Copia el archivo a una carpeta fija, por ejemplo ~/Aplicaciones/. Si lo mueves después, los accesos directos dejan de funcionar.
  2. Dale permiso de ejecución. Desde el explorador de archivos: clic derecho, Propiedades, Permisos, marcar Permitir ejecutar el archivo como un programa. Desde la terminal:
chmod +x ~/Aplicaciones/FrontTRT-1.0.0.AppImage
  1. Haz doble clic en el archivo.
Error de FUSE

Si el AppImage no abre y la terminal menciona FUSE o libfuse.so.2, instala la biblioteca: sudo apt install libfuse2. En Ubuntu 24.04 el paquete se llama libfuse2t64. Otra opción es instalar el .deb.

6.2 Linux con .deb

sudo apt install ./front-trt_1.0.0_amd64.deb

El ./ es necesario para que apt instale el archivo local en lugar de buscarlo en los repositorios. La aplicación aparece en el menú como FrontTRT. Para quitarla: sudo apt remove front-trt.

6.3 Windows

  1. Haz doble clic en FrontTRT Setup 1.0.0.exe.
  2. El instalador no está firmado, así que Windows puede mostrar Windows protegió su PC. Pulsa Más información y luego Ejecutar de todas formas. Si el antivirus pone el archivo en cuarentena, agrégalo como excepción.
  3. El instalador termina sin hacer preguntas, crea los accesos directos y abre la aplicación.

Se instala solo para la cuenta de Windows que lo ejecutó. Para quitarla: Configuración, Aplicaciones, FrontTRT, Desinstalar.

7 Verificar la instalación

Responsable de sistemas

Haz esta revisión en cada caja, con un usuario real de esa sucursal, antes de entregarla.

  • La aplicación abre y muestra la pantalla de acceso.
  • El inicio de sesión entra al punto de venta. La primera vez del día puede tardar hasta un minuto mientras Render despierta.
  • La barra superior muestra el usuario y la etiqueta SUC-# de la sucursal correcta.
  • El punto de venta lista productos con existencias. Si la lista sale vacía, la sucursal no tiene inventario cargado.
  • El lector de código de barras agrega un producto al carrito con una sola lectura.
  • Historial carga las ventas de la sucursal.
  • Con un usuario de gerente, Reportes genera y abre el PDF del día.
  • Cerrar sesión regresa a la pantalla de acceso.
Venta de prueba

Una venta de prueba descuenta existencias reales y el cajero no puede cancelarla. Si necesitas probar el cobro, hazlo con un producto de prueba y pide al administrador que ajuste el inventario después.

Reportes

La aplicación de escritorio bloquea las ventanas nuevas, y Reportes abre el PDF en una. Es probable que en la versión instalada el reporte no se abra. Si pasa, anótalo como falla conocida y genera los reportes desde la versión web (capítulo 9) mientras se corrige.

8 Actualizar y revertir

Responsable de sistemas

La aplicación no se actualiza sola. Cada versión nueva se instala a mano en cada caja, fuera del horario de venta.

FormatoCómo actualizar
AppImageCierra la aplicación, reemplaza el archivo por el nuevo y dale permiso de ejecución otra vez.
.debsudo apt install ./front-trt_X.Y.Z_amd64.deb. apt reemplaza la versión instalada.
WindowsCierra la aplicación y ejecuta el Setup nuevo. Reemplaza la versión anterior.

Revertir

Guarda los instaladores de cada versión liberada fuera de dist_electron/, en una carpeta con el número de versión. Si la versión nueva falla, instala la anterior de la misma forma. En .deb, apt puede pedir confirmación para bajar de versión: sudo apt install --allow-downgrades ./front-trt_X.Y.Z_amd64.deb.

Datos

Actualizar o revertir la aplicación no toca ventas, inventario ni usuarios, porque viven en el backend. Lo único local es la sesión guardada, que a lo mucho obliga a iniciar sesión otra vez.

9 Publicar como sitio web

Responsable de sistemas

El destino oficial es la aplicación de escritorio. Si hace falta abrir el sistema desde un navegador, por ejemplo para generar reportes, la misma compilación sirve como sitio estático. En el navegador la impresión de tickets queda desactivada.

  1. Compila con base absoluta. La configuración de producción usa baseHref: "./" para Electron; en un servidor web eso rompe la carga de archivos al recargar una ruta interna.
npx ng build --configuration=production --base-href /
  1. Sube el contenido de dist/front-trt/browser/ a cualquier servidor de archivos estáticos.
  2. Configura el servidor para que responda index.html a cualquier ruta que no sea un archivo. Sin eso, recargar en /sales da 404.
  3. En Render, agrega el dominio del sitio a CORS_ALLOWED_ORIGINS (sección 10.2). Sin ese permiso, el navegador bloquea las peticiones a la API.

Ejemplo de regla de respaldo en nginx:

location / {
  try_files $uri $uri/ /index.html;
}
No usar ng serve

npm start y npm run web levantan el servidor de desarrollo, sin optimizar y con el entorno de desarrollo. No sirven para publicar.

10 Desplegar el backend

Responsable de sistemas

El backend, repositorio RefaccionariaBack, no se compila a mano: GitHub lo prueba y lo publica en Render. La base de datos de producción es PostgreSQL en Neon. El detalle técnico está en el capítulo 14 del Manual técnico.

10.1 Flujo de publicación

  1. Sube los cambios a la rama test, con push o con un pull request.
  2. GitHub Actions corre el flujo Tests: análisis con ruff y la suite completa de pytest sobre PostgreSQL 17. Síguelo en la pestaña Actions del repositorio.
  3. Si todo pasa, el mismo flujo hace merge de test en Develop y lanza Deploy to Render.
  4. Render construye y arranca la versión nueva. Revisa en su panel que el despliegue termine en verde.

Si las pruebas fallan, no se hace merge ni se publica nada. Un push directo a Develop también despliega, pero se salta las pruebas; evítalo.

Secreto de GitHub

El despliegue usa el secreto RENDER_API_KEY, guardado en la configuración del repositorio en GitHub. Si la llave de Render cambia, actualízala ahí o el paso de despliegue fallará.

10.2 Configuración en Render

Estas variables se definen en el panel del servicio en Render, en la sección de variables de entorno:

VariableValor en producción
SECRET_KEYUna cadena larga, secreta y fija. Si cambia, los tokens emitidos dejan de valer y todos tienen que volver a iniciar sesión.
DEBUGNo definirla, o False.
DATABASE_URLCadena de conexión de Neon.
CORS_ALLOWED_ORIGINSEl dominio de la versión web, si la publicas (capítulo 9).
NOTIFICATIONS_LOW_STOCK_THRESHOLDOpcional. Piezas por debajo de las cuales se avisa stock bajo; 10 si no se define.
Datos fuera del repositorio

Los comandos de compilación y de arranque del servicio solo existen en el panel de Render. Anótalos junto con este manual; si el servicio se pierde, no hay otra copia. El dominio refaccionariaback.onrender.com está escrito en ALLOWED_HOSTS de RTR/settings.py: cambiar de dominio requiere un cambio de código.

10.3 Migraciones en producción

Una versión que cambia modelos trae migraciones. Antes de aplicarlas, sigue docs/RUNBOOK_migracion.md del backend:

  1. Saca un respaldo (snapshot) de la base en Neon.
  2. Publica la versión nueva con el flujo de la sección 10.1.
  3. Revisa si el comando de arranque de Render ya ejecuta migrate. Si no, ejecútalo desde una terminal con el entorno del backend y la DATABASE_URL de producción:
python manage.py showmigrations   # pendientes marcadas con [ ]
python manage.py migrate
  1. Verifica con un usuario de cada rol: inicio de sesión, una venta, un reporte con el encargado y el alta de un usuario con el admin.

Si algo falla, restaura el snapshot de Neon y vuelve a desplegar la versión anterior.

Migración rota

En la copia local de RefaccionariaBack hay un archivo sin seguimiento, producto/migrations/0003_rename_codigosat_producto_codigo_sat.py, que hace fallar migrate con NodeNotFoundError. No lo subas al repositorio y no ejecutes migrate contra producción desde una copia que lo tenga.

11 Preparar una sucursal

Responsable de sistemas

Antes de instalar la aplicación en una caja, la sucursal tiene que existir en el backend con sus usuarios, métodos de pago e inventario. Sin eso, la caja abre pero no puede vender.

11.1 Primer administrador

Solo hace falta una vez, cuando la base está vacía o no hay ningún admin.

  1. Crea un superusuario desde una terminal con el entorno del backend apuntando a producción: python manage.py createsuperuser.
  2. Entra a https://refaccionariaback.onrender.com/admin/ con ese usuario.
  3. En Perfils, agrega uno para ese usuario con rol admin y una sucursal.
Sin Perfil

Un superusuario sin Perfil entra a la aplicación como cajero y no ve Administración. El paso 3 no es opcional.

11.2 Sucursal y usuarios

Con el usuario admin, desde la aplicación:

  1. Registra la sucursal en Sucursales con Registrar Sucursal, o desde el formulario de sucursal de Administración.
  2. En Administración, llena el formulario de usuario: Usuario, Correo, Contraseña, Sucursal, Rol y Estado. Pulsa Crear usuario.
  3. Crea al menos un encargado y los cajeros de esa sucursal.

La pantalla Cajeros del encargado todavía no guarda datos, así que en la versión 1.0 todas las altas las hace el admin.

11.3 Catálogos e inventario inicial

DatoDónde se capturaNotas
Métodos de pagoPanel /admin/, Metodo pagosSon globales. Basta con crearlos una vez (por ejemplo Efectivo y Tarjeta).
CategoríasPanel /admin/, TiposGlobales. Son las categorías del punto de venta.
ProductosAplicación, InventarioEl catálogo es común a todas las sucursales.
ExistenciasAplicación, Inventario Sucursal, movimiento de EntradaLo hace el encargado de la sucursal. Sin existencias, el punto de venta sale vacío.
Precio de sucursalAplicación, Precios por SucursalOpcional. Sin él, la sucursal vende al precio general.
No editar Stock en /admin/

El panel de Django permite cambiar la tabla Stock directamente, pero así no queda movimiento ni se evalúan las alertas. Las existencias se cargan siempre con movimientos de entrada desde la aplicación.

12 Solución de problemas

Responsable de sistemas

Qué pasaQué hacer
EACCES: permission denied al compilar.Hay archivos de root que dejó Docker. Corre el chown del capítulo 4.
Docker no está instalado al correr build:installer:win.Instala Docker o compila desde Windows (sección 5.3). Si está instalado, revisa que el servicio corra y que tu usuario pueda usarlo sin sudo.
Falla el .deb con un error sobre ar.Falta binutils: sudo apt install binutils.
npm run electron:prod dice No se encontró index.html de Angular en dist.Falta la compilación o quedó incompleta. Corre npm run build:prod y revisa que exista dist/front-trt/browser/index.html.
electron-builder se detiene descargando Electron.Necesita internet la primera vez. Revisa la conexión o el proxy y repite.
El AppImage no abre.Revisa el permiso de ejecución. Si menciona FUSE, instala libfuse2 (sección 6.1).
Windows borra o bloquea el instalador.Es SmartScreen o el antivirus, porque el instalador no está firmado (sección 6.3).
El inicio de sesión tarda o falla la primera vez del día.Render apaga el backend gratuito cuando no hay uso y tarda hasta un minuto en despertar. Espera e intenta otra vez.
Error de red al iniciar sesión en todas las cajas.Revisa que https://refaccionariaback.onrender.com/api responda desde un navegador. Si no responde, el problema está en el backend.
Inicia sesión pero dice Tu usuario no tiene sucursal asignada.El admin debe asignarle sucursal en Administración (sección 11.2).
Un administrador entra y no ve Administración.Le falta un Perfil con rol admin (sección 11.1).
El punto de venta no muestra productos.La sucursal no tiene existencias. El encargado debe registrar entradas (sección 11.3).
No aparecen las formas de pago al cobrar.Faltan métodos de pago en el panel /admin/ (sección 11.3).
El flujo Tests falla en GitHub.No se publica nada. Revisa el registro en Actions, corrige en test y vuelve a subir.
El paso Deploy to Render falla.Revisa el secreto RENDER_API_KEY en GitHub (sección 10.1).
La API responde 400 a todo después de cambiar de dominio.El dominio nuevo no está en ALLOWED_HOSTS (sección 10.2).
migrate falla con NodeNotFoundError.Hay una migración rota en la copia del backend (sección 10.3). Apártala y repite.
Todos tienen que iniciar sesión otra vez tras un despliegue.Cambió SECRET_KEY en Render. Déjala fija (sección 10.2).
No sale el ticket impreso.La versión 1.0 no envía el ticket a la impresora (sección 2.2). Consulta la venta en Historial.
El reporte no abre en la app de escritorio.Falla conocida probable (capítulo 7). Genera el reporte desde la versión web (capítulo 9).

13 Lista de liberación

Responsable de sistemas

Imprime esta página y márcala en cada liberación.

Antes de compilar

  • Rama y commit a liberar anotados.
  • "version" de package.json aumentada.
  • apiUrl de environment.prod.ts revisada.
  • Si la versión necesita cambios del backend: flujo Tests en verde, despliegue en Render terminado y migraciones aplicadas.
  • npm ci sin errores.
  • npm run lint, npm run test:coverage y npm run e2e en verde.
  • Sin archivos de root en dist/ ni dist_electron/.

Compilación

  • npm run build:installer generó el AppImage y el .deb con la versión nueva.
  • npm run build:installer:win generó el Setup .exe con la versión nueva.
  • chown después de Docker.
  • Instaladores copiados a una carpeta con el número de versión, junto con los de la versión anterior.

Instalación

  • Instalado y verificado en una caja piloto (capítulo 7).
  • Instalado en el resto de las cajas fuera del horario de venta.
  • Cada caja verificada con un usuario de su sucursal.
  • Fallas encontradas anotadas con hora, caja y mensaje exacto.
